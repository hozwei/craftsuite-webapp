# Troubleshooting

Start with `docker exec craft-update craft-update --status` and the logs of the container
concerned ([operations.md](operations.md#status-and-logs)).

## Signing in

| Symptom | Cause and fix |
|---|---|
| `craft-gate` restarts again and again; its log says `Failed to initialise OAuth2 Proxy` or something about the issuer | oauth2-proxy could not fetch `<issuer>/.well-known/openid-configuration` at start, or the issuer there differs from `CRAFT_OIDC_ISSUER_URL`. Compare character by character (plain slashes, none at the end, no `index.php`); check that the Docker host reaches the provider's public address (inside the same network this may need hairpin NAT or split DNS). |
| After the sign-in: an error page from oauth2-proxy with "CSRF" or status 500 | The sign-in took longer than 15 minutes, or cookies were blocked. Open `https://craft.example.com` again. If it stays, see the `craft-gate` log. |
| `invalid_client` in the `craft-gate` log | `CRAFT_OIDC_CLIENT_SECRET` does not match the client at the provider. Nextcloud then slows down further attempts from the address it sees for these requests (brute-force protection): after fixing the secret, `occ security:bruteforce:reset <ip>` with that address (your public IP if the request goes through hairpin NAT, else the Docker host's; Nextcloud's log names it). |
| Nextcloud shows "Access forbidden … not a member of the groups defined for the client" | The account is not in the group the client is limited to. |
| `https://craft.example.com` answers `502` or `504` | The reverse proxy does not reach `CRAFT_PORT`, or `craft-web` is not running (`docker compose ps`). |
| `craft-web` restarts; its log says `CRAFTSUITE_ALLOWED_ORIGINS …` | The value is not a list of origins: use `https://host` or `https://host:port`, separated by spaces (no commas, no path, no slash at the end). |
| `craft-web` answers `500` (and `502` under `/oauth2/`) | It cannot reach `craft-gate` (`docker logs craft-web`). Is `craft-gate` running and healthy? |
| Signed out at the provider, but the apps still open | Expected: the session at the gate lasts `CRAFT_SESSION_LIFETIME`. Sign out at `https://craft.example.com/oauth2/sign_out` as well. |

## Updates

| Log line of `craft-update` | Meaning and fix |
|---|---|
| `<app>: ERROR - cannot list the releases of <repo> …` | No answer from `api.github.com`, the 60 requests per hour for your IP address are used up (other machines behind the same address count too), or there is no such repository: for an app that the layer's app list does not have, the name in `CRAFT_APPS` must be a repository at `github.com/storytold/<app>`. The updater tries again in an hour. |
| `ERROR - checksum of … does not match, nothing changed` | The download differs from `SHA256SUMS.txt` or from GitHub's digest. Nothing was switched. If it repeats, look at the release on GitHub before doing anything else. |
| `ERROR - … has links or paths outside …` / `unexpected content in …` | The release archive does not have the expected layout. Nothing was switched; the app's maintainers may have changed their packaging. |
| `<app>: <version> stays, no newer release qualifies yet (<newer>: <reason>)` or `<app>: not installed yet, no release qualifies yet; a later run takes one (<newer>: <reason>)` | The app's newest release that is newer than the installed one waits, and the reason says for what: `it is younger than CRAFT_MIN_AGE_HOURS`, `no canary run of layer <layer> after it yet`, or `its first canary run of layer <layer> has not ended yet`. A later run takes it; or update now ([operations.md](operations.md#update-now)). Without a reason, no newer release is out. |
| `… (<newer>: its first canary run of layer <layer> failed for it; the app's next release that passes its first run comes, or take <newer> now: operations.md, Update now)` (also `did not test it`, `is no longer among the last 100`) | That release does not come with your layer version: its first canary run of your layer version failed for the app, tested another version, or is no longer listed ([how-it-works.md](how-it-works.md#the-canary), rule 2). The app's next release comes once it passes its own first run, or with a newer layer version whose first run passes it. To take this one untested: [update now](operations.md#update-now) with `-e CRAFTSUITE_CANARY=off`. |
| `<app>: not installed yet, no release from <minVersion> on yet (the oldest that layer <version> handles, its app list)` | Every release of the app is older than the app list's `minVersion`, which the layer's adapter does not handle. The app comes with its first release from that version on. |
| `<app>: not installed yet, <version> waits (<reason>)` or `<app>: <version> held back (<reason>), <old> stays` | The release qualifies but is held back, for the reason given: `open canary issue` (no error), `canary failure`, `canary runs not readable` (or `translator versions`, `issues`, `comments`), `app list not readable` or `layer not available`; see the rows of those messages. The installed version stays, and an app that is not installed yet waits, without an error of its own. |
| `<app>: ERROR - <version> is older than <minVersion>, the oldest release layer <version> handles (its app list): it is served without the Nextcloud integration until a newer release is taken` | The version being served is below the app list's `minVersion`: after a rollback, or because a newer layer release raised it. Its translator has been removed, since the layer's adapter does not handle it. The error ends once a newer release is taken; after a rollback, that is one above the blocked version ([operations.md](operations.md#roll-back)). |
| `<app>: ERROR - no release v<version> with <app>-web-<version>.zip and SHA256SUMS.txt found` | The app's releases do not have the expected form (tag, web build, checksum file); check `CRAFT_APPS` and the app's releases on GitHub. |
| `layer: ERROR - checksum of craftsuite-layer-hosting-… does not match …` | `CRAFTSUITE_LAYER_SHA256` is not the checksum of that version's bundle. Copy it again from the release's `SHA256SUMS`. New releases wait until it is fixed. |
| `layer: ERROR - CRAFTSUITE_ALLOWED_ORIGINS is empty` | The layer is on but no Nextcloud origin is set. Set it, or empty `CRAFTSUITE_LAYER_VERSION`. |
| `layer: ERROR - CRAFTSUITE_STARTUP_TIMEOUTS takes entries such as lightcraft=180000 …` | The value is not a list of `app=milliseconds` entries separated by spaces, or a value is above 2147483647. Until it is fixed, the layer counts as not available: new releases wait, and every run has an error. |
| `inject-translator: error: invalid allowed origin …` and `translator not added to … (inject-translator.sh exit code 2)` | The translator refuses a value in `CRAFTSUITE_ALLOWED_ORIGINS` (https only, no path, international names in their `xn--` form). Until it is fixed, no release is switched to; on a first installation no app appears. |
| `translator not added to … (inject-translator.sh exit code 4)` | The release's `index.html` changed in a way the translator's injector does not handle. That release is not switched to; the layer needs an update. |
| `layer … has no adapter for <app>, … served without the Nextcloud integration` | This layer version does not support that app. It is served without the translator, and `--status` shows `Nextcloud no` for it. Layer 0.1.0 has none for WordCraft, GridCraft, DeckCraft, CADCraft, LightCraft, FilmCraft and EffectCraft, 0.2.0 to 0.4.2 have one for these eleven apps, and 0.5.0 and later also for SoundCraft ([operations.md](operations.md#upgrading-nextcloud-craftsuite-layer)). |
| Every page answers `403` | `CRAFT_DATA_DIR` is not readable for others; `craft-web` reads it as user 101: `chmod 755 <CRAFT_DATA_DIR>`. |
| `ERROR - <folder> … must be writable for user …` | `CRAFT_DATA_DIR` or a folder in it does not belong to `CRAFT_USER`: `chown -R <CRAFT_USER> <CRAFT_DATA_DIR>`. |
| `craft-update is already running` | Another run is in progress (a manual one, or the retry an hour after an error). If none is, the lock is left from a killed run: restarting the container removes it. |
| `ERROR - state/<app>.blocked holds '…'` | The block file must hold a version such as `0.7.0`. |

### The app list

| Log line of `craft-update` | Meaning and fix |
|---|---|
| `ERROR - CRAFT_APPS: '<word>' is neither auto, an app such as pdfcraft, nor -<app> to leave one out` | A word in `CRAFT_APPS` is not `auto`, an app id (lowercase letters and digits, starting with a letter) or `-<app>` (characters outside these show as `?`). It is ignored, the rest applies ([configuration.md](configuration.md#the-app-list)); a list of nothing but such words keeps the installed apps. |
| `ERROR - CRAFT_APPS ('<value>') stands for no app: name apps such as pdfcraft, or use auto` | No app is left: the exclusions leave out every app. Name the apps, or use `auto` ([configuration.md](configuration.md#the-app-list)). |
| `ERROR - CRAFT_APPS=auto takes its apps from the app list of nextcloud-craftsuite-layer, and no layer is set (CRAFTSUITE_LAYER_VERSION): name the apps in CRAFT_APPS, such as pdfcraft photocraft` | Without the Nextcloud integration there is no app list, and no app is installed yet. Name the apps, or turn the integration on with layer 0.5.0 or later ([nextcloud.md](nextcloud.md#2-open-files-from-nextcloud)). |
| `CRAFT_APPS=auto without nextcloud-craftsuite-layer: the installed apps are kept up to date; name new apps in CRAFT_APPS` | Not an error: without the integration there is no app list, so `auto` stands for the apps installed. Name an app in `CRAFT_APPS` to add it. |
| `layer: layer <version> has no app list (apps.json comes with layer 0.5.0 and later): no names, colours, startup timeouts or oldest releases from it; …` | Not an error on its own: a layer before 0.5.0 has no app list. The start page shows the app ids, and no `minVersion` applies; set `CRAFTSUITE_STARTUP_TIMEOUTS=lightcraft=180000 effectcraft=180000` ([configuration.md](configuration.md#nextcloud-integration)). With `CRAFT_APPS=auto`, every run also has `ERROR - CRAFT_APPS=auto: layer <version> has no app list …; name the apps in CRAFT_APPS (the installed ones are kept up to date)`: name the apps, or move to layer 0.5.0 or later. |
| `layer: ERROR - the app list of layer <version> (apps.json) cannot be read: new releases wait, and the translators stay as they are` or `… (apps.json) has format <format>, this updater reads format 1: …` | The bundle's `apps.json` is not a JSON object with its apps, or has a format this release does not read (a newer layer may need a newer craftsuite-webapp). Nothing changes: no new release of any app is taken (`held back (app list not readable)`), the translators stay as they are, and the start page keeps the last app list that could be read (`state/app-list`). Go back to a layer version this release reads, or update craftsuite-webapp. |
| `layer: ERROR - entries of the app list of layer <version> (apps.json) are invalid, their new releases wait: <app> (<field>), …` | An entry of the layer's app list has an invalid id, entry, `repo` or `minVersion`; the line names the field. That app (with `auto` or named in `CRAFT_APPS`) gets no update and its served version stays as it is, with an error on every run (`<app>: ERROR - its entry in the app list of layer <version> is invalid: <version> stays, without changes`). The fault is in the layer release: report it there, or go back to the previous layer version. |
| `<app>: not in the app list of layer <version>, which does not test it: its releases are taken by age alone` | An app named in `CRAFT_APPS` that the layer does not list (no adapter): its canary never tests it, so only `CRAFT_MIN_AGE_HOURS` applies. It is served without the Nextcloud integration. |
| `<app>: <version> is served, but the app list of layer <version> no longer has it: no updates and no Nextcloud integration (operations.md, Removing an app)` | With `auto`, the layer's app list does not have that app (any more), so its translator is removed. It stays reachable at `/<app>/`, but not on the start page. [Remove it](operations.md#removing-an-app), or name it (`auto <app>`) to keep it updated from `github.com/storytold/<app>`, where the layer may have no adapter for it. |
| `<app>: <version> is served but not in the app list (CRAFT_APPS), so it gets no updates (operations.md, Removing an app)` | The app is left out (`-<app>`, or missing from a list of ids) but still installed. It stays reachable at `/<app>/`, with the translator it has, but not on the start page. [Remove it](operations.md#removing-an-app), or add it to `CRAFT_APPS` again. |

### The canary

| Log line of `craft-update` | Meaning and fix |
|---|---|
| `layer: the canary reports a failure for <apps> (<issue>), their new releases wait while the issue is open` or `… for every app (<issue>), new releases wait while the issue is open` | A `canary` issue is open and names these apps (in its reports or its `canary:<app>` labels), or names none, which counts for every app (an issue opened before layer 0.5.0, say). Their new releases wait until the issue is closed, without an error (rule 1, [how-it-works.md](how-it-works.md#the-canary)); an app that is not installed yet waits too (`not installed yet, <version> waits (open canary issue)`). If a run of your layer version failed since it came into use, the next row applies as well. |
| `layer: ERROR - the canary failed for <apps> (<link>) since layer <version> came into use: their new releases wait until another layer version is in use, or you confirm …` or `… failed for every app (<link>) …` and `<app>: <version> held back (canary failure), <old> stays` | A canary run of your layer version, created since that version came into use, failed for these apps (rule 3). The link is its issue, or the run when it opened none. Their new releases wait until another layer version is in use or you confirm, also after the issue is closed: [operations.md](operations.md#the-canary-hold). A `state/canary-failed` from craftsuite-webapp 0.3.0 holds every app. A failure only of apps that are not served here holds nothing: `layer: the canary failed for <apps> (<link>) since layer <version> came into use; none of them is served here`, no error. |
| `layer: ERROR - cannot read the canary runs of <repo>, new releases wait` (or `translator versions`, `issues`, `comments`) | Runs, issues, comments: the GitHub API did not answer, the 60 requests per hour for your IP address are used up, or the answer was empty or not a list (for example a 404 because the repository in `CRAFTSUITE_LAYER_REPO` has no workflow `canary.yml`). Translator versions: `raw.githubusercontent.com` did not answer with `translators/core.js` (or a 404) for a commit the canary ran on, or the file has no `LAYER_VERSION`. No new release of any app is taken (`<app>: <version> held back (canary runs not readable)`, and so on); an app that is not installed yet waits. The updater tries again in an hour. |
| `layer: no canary run has tested layer <version> yet; new releases wait for one` | Not an error: no finished canary run of your layer version is listed yet, as right after a move to a new layer version, before the canary has run on it. New releases wait for one. Three days after the version came into use, this becomes an error (`no canary run has tested layer <version> since it came into use …`, below). |
| `layer: canary runs since <time> test a newer layer version than <version> (the newest: <newer>): releases that came out since wait until a newer layer version is in use (how-it-works.md, The canary)` | Not an error yet: a newer layer release is out, and the canary tests it, not yours. Releases of the apps that come out now wait for a run of your layer version, which will not come: [upgrade the layer](operations.md#upgrading-nextcloud-craftsuite-layer). Three days after the newest run of your version, this becomes an error (next row). |
| `layer: ERROR - the newest canary run of layer <version> started <time>, more than three days ago; runs since then test a newer layer version (the newest: <newer>): new releases wait until a newer one is in use (operations.md, Upgrading nextcloud-craftsuite-layer)` (or `no canary run has tested layer <version> since it came into use <time>, more than three days ago; runs since then test a newer layer version …`) | The canary has moved on to a newer layer release. [Upgrade the layer](operations.md#upgrading-nextcloud-craftsuite-layer); the error ends with it. Releases that a run of your version tested are still taken meanwhile. |
| `layer: ERROR - the newest canary run of layer <version> started <time>, more than three days ago: releases that came out since wait for a run (how-it-works.md, The canary)` | For more than three days, no canary run of your layer version has started that counts (one that ended with `success` or `failure`): GitHub delayed or skipped the scheduled runs, or turned the schedule off after 60 days without activity, or the runs were cancelled. Releases that an earlier run tested are still taken, newer ones wait for a run; to take one untested, run the updater once with `-e CRAFTSUITE_CANARY=off` ([operations.md](operations.md#update-now)). The error cannot be acknowledged: it goes away once such a run has ended, or with `CRAFTSUITE_CANARY=off` in `.env`, which turns off the whole canary check. |
| `layer: ERROR - no canary run has tested layer <version> since it came into use <time>, more than three days ago: releases that came out since wait for a run (how-it-works.md, The canary)` | Your layer version came into use more than three days ago, and none of the canary's last 100 runs that have ended tested it: the canary has not run since, or your layer version is older than all of these runs. Move to the layer version the canary tests ([operations.md](operations.md#upgrading-nextcloud-craftsuite-layer)), or see the row above for a canary that stopped. |
| `layer: ERROR - the canary of <repo> has no finished run: new releases wait for one (how-it-works.md, The canary)` | None of the canary's last 100 runs on `main` ended with `success` or `failure`, and none is a re-run that ended `cancelled`, so no new release counts as tested ([how-it-works.md](how-it-works.md#the-canary)). With a fork in `CRAFTSUITE_LAYER_REPO`, check that Actions and the canary's schedule are on in it. |

## In Nextcloud

| Symptom | Cause and fix |
|---|---|
| No "Open in …" entries in Files | The app is not enabled for you (`occ app:list`, `occ config:app:get craftsuite_layer enabled`), or that Craft app has no address, neither its own nor the one for all apps (`occ config:list craftsuite_layer`: `<app>_url`, `apps_base_url`), or it is switched off (`<app>_disabled`), or the address is refused (since 0.2.0 also one with a query, `?…`): see *Administration settings* → *Craft apps*. |
| The editor shows after 15 seconds "… has not answered yet" | The frame shows a sign-in (follow the link in the hint, sign in, reload), or the app may not be framed: `CRAFTSUITE_ALLOWED_ORIGINS` must contain your Nextcloud's address exactly as the browser shows it, and `--status` must show `Nextcloud yes`. Check the headers with `curl -sI https://craft.example.com/` (`frame-ancestors` with your Nextcloud, no `x-frame-options`). |
| "… did not start. Is it reachable at …?" after 90 seconds | The app does not load in the frame at all; same checks as above, and the browser console of the frame. LightCraft and EffectCraft on a slow first load (below about 2 Mbit/s) get this message too: the editor page waits a fixed 90 seconds, which `CRAFTSUITE_STARTUP_TIMEOUTS` does not change. Then it is provisional, and the file opens once the app has started. From Nextcloud app 0.5.1 on, the link to the app in a new tab stays next to the message. |
| "… could not start: the app did not start in time" while LightCraft, EffectCraft or FilmCraft load for the first time | Their large downloads do not hold back the page's `load` event, so the translator's start timer runs while they are still loading: 180 seconds for LightCraft and EffectCraft, as the layer's app list recommends (or what `CRAFTSUITE_STARTUP_TIMEOUTS` sets), the translator's 60 seconds for FilmCraft. The message is provisional: once the app has started, it gets the file after all. For slow connections, raise the values or add `filmcraft=180000` ([configuration.md](configuration.md#nextcloud-integration)) and run `docker compose up -d`; the run that follows updates the served versions. |
| "… could not start: the app registered no drop target" / "failed to start" | The browser lacks WebGL 2 or the app failed to start; try the app directly at `https://craft.example.com/<app>/`. |
| Saving a SoundCraft session fails, and the browser downloads it instead | Each save uploads the whole session with its audio in one request, tens of MB and more; the reverse proxy or web server in front of Nextcloud refuses or cuts off such a large request (nginx: `client_max_body_size`, 1 MB by default). Allow large request bodies there ([nextcloud.md](nextcloud.md#soundcraft-sessions)). The status line of the editor page says why the save failed. |

The editor page's messages are explained in the layer's
[Nextcloud app documentation](https://github.com/hozwei/nextcloud-craftsuite-layer/blob/v0.5.1/docs/nextcloud-app.md).

## The apps

| Symptom | Cause and fix |
|---|---|
| An app stays on its loading screen | Reload. If it stays, open the app directly with `?webgl` at the end of its address (forces WebGL 2; read by PhotoCraft, VectorCraft, DesignCraft, WordCraft, GridCraft, DeckCraft, CADCraft and FilmCraft) or `?cpu` (PhotoCraft and FilmCraft only). PdfCraft, LightCraft and EffectCraft read neither. Not in Nextcloud: the Nextcloud app refuses app addresses with a query. |
| The start page shows a red notice | The last update run had an error; the apps run in their previous version. See the log of `craft-update`. The notice "No app is installed yet; the log of craft-update says why." shows whenever no app is installed, also after a run without errors: then no release qualifies yet, as on a new data folder until a release of an app has passed the first canary run of your layer version after it and is `CRAFT_MIN_AGE_HOURS` old ([operations.md](operations.md#backups-and-rebuilding)). A notice that names apps and links a canary issue or run: [the canary hold](operations.md#the-canary-hold). |
| A new version does not appear | Browsers load it on the next page load; the update runs daily at `CRAFT_UPDATE_TIME` and takes a release only when it qualifies (age, canary). EffectCraft, in a browser that opened it directly while it was served with its own service worker (without the integration or with layer 0.1.0): the first load after the layer has replaced the worker still comes from that worker's cache, every later one from the server. |
